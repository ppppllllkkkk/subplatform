# Subcontractor Platform — Backend

FastAPI-сервис. Эндпоинты:
- **SRF → RFQ** — чтение полей SRF (PDF) и генерация заполненного RFQ (.docx),
  без ИИ, через `pdfplumber` / `python-docx`.
- **CBE** — сравнение ценовых предложений нескольких поставщиков: чтение PDF
  (текстовых и сканов через OCR), сопоставление с фиксированным списком курсов
  по словарю ключевых слов (без ИИ), сборка итогового `.xlsx` с сохранением
  формул сравнения.

## Структура

```
main.py             — FastAPI-приложение, роуты
srf_extract.py       — извлечение полей SRF (по подписям, детерминированно)
rfq_generate.py       — заполнение RFQ-шаблона (.docx)
cbe_data.py            — 10 курсов + 7 вендоров + ключевые слова для сопоставления
cbe_extract.py          — чтение вендорских PDF (текст через pdfplumber, сканы — OCR)
cbe_match.py             — сопоставление строк с курсами по словарю, без ИИ
cbe_generate.py           — заполнение CBE-шаблона (.xlsx) подтверждёнными ценами
templates/                — пустые шаблоны-заготовки (rfq_template.docx, cbe_template.xlsx)
requirements.txt
Dockerfile                 — нужен для Render: ставит tesseract/poppler (OCR),
                              которых нет в обычном Python-окружении
render.yaml                 — Render Blueprint, сборка через Docker
```

## ⚠️ Важно: OCR требует Docker

Начиная с CBE, бэкенд умеет читать сканы (не только текстовые PDF) — через
`tesseract` + `poppler-utils`. Это **системные** пакеты, их нельзя поставить
через `pip`/`requirements.txt`. Локально их нужно поставить руками (см. ниже),
а на Render — обязательно через `Dockerfile` (обычный Python-buildpack Render
их не поставит, и OCR будет падать с ошибкой "tesseract not found").

## Локальный запуск

**Системные зависимости (один раз, вне venv):**

```bash
# macOS
brew install tesseract tesseract-lang poppler

# Ubuntu/Debian
sudo apt-get install tesseract-ocr tesseract-ocr-rus poppler-utils
```

**Дальше как обычно:**

```bash
cd backend
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

Проверить: `curl http://localhost:8000/api/health` → `{"status":"ok"}`

Фронтенд (Vite) уже настроен проксировать `/api/*` на `http://localhost:8000` (см.
`vite.config.js` в проекте фронтенда) — при локальном запуске обоих сразу всё
должно заработать без дополнительной настройки.

## Деплой на Render

Единый `render.yaml` в корне репозитория (Blueprint) описывает **оба** сервиса —
этот backend (Docker) и frontend (статика) — и сам связывает их адреса друг с
другом. Подробности и пошаговая инструкция — в корневом `README.md`.

Если нужно задеплоить только backend вручную (без Blueprint):
1. New → Web Service → подключите репозиторий.
2. Root Directory: `backend`. Runtime: **Docker** (не Python! иначе OCR не будет
   работать) — Render сам найдёт `Dockerfile` и соберёт образ.
3. В Environment добавьте переменную `FRONTEND_ORIGIN` — адрес фронтенда без
   схемы или с ней (например, `your-frontend.onrender.com`) для настройки CORS.

## Фронтенд и адрес бэкенда

Фронтенд ходит на адрес из `VITE_API_URL` (см. `frontend/src/lib/api.js`) —
пусто/не задано означает относительный путь `/api/...`, который в dev-режиме
проксируется в `localhost:8000` (см. `vite.config.js`). В проде эту переменную
подставляет `render.yaml` при сборке фронтенда автоматически.

## CBE: как устроено сопоставление

`cbe_data.py` хранит 10 фиксированных курсов (с ключевыми словами на русском и
английском) и 7 фиксированных вендоров шаблона. `cbe_match.py` ищет для каждой
строки вендорского предложения совпадения по словарю:
- **1 совпадение** → считается надёжным (`status: matched`)
- **0 или 2+ совпадений** → помечается (`status: unmatched` / `ambiguous`) и
  **не проставляется автоматически** — фронтенд показывает список вариантов,
  человек выбирает сам.

Проверено на трёх реальных предложениях (2 текстовых + 1 скан) — 0 ошибочных
автоматических сопоставлений, все спорные случаи (объединённые курсы у одного
вендора, дублирующиеся тарифы ИТР/рабочий у другого) корректно попадают в
`ambiguous`, а не угадываются наугад.

## Что дальше

- Автоматическое определение вендора для сканов работает хуже, чем для текстовых
  PDF (название компании часто на печати/логотипе, а не в обычном тексте) —
  сейчас в таком случае просто предлагается выбрать вендора вручную.
- Пока не реализовано: сохранение оформления при дозаписи категорий Excel-базы
  (аналогично RFQ и CBE, но для Subcontractor Database) — логика та же
  (`openpyxl`, копирование стиля ячеек), просто ещё не обёрнута в эндпоинт.
- Хранение данных (сейчас на фронтенде — `localStorage`) — потребуется база данных
  и эндпоинты для чтения/записи, когда встанет вопрос многопользовательской работы.
