# Subcontractor Platform

Веб-приложение для работы с базой субподрядчиков и генерации документов (RFQ из SRF) на этапе Pre-award.

## Структура проекта

```
src/
  main.jsx                    — точка входа
  App.jsx                     — состояние приложения, переключение секций
  styles.js                   — общие стили компонентов (inline-style объекты)
  styles.css                  — глобальные стили, шрифты, анимации
  lib/
    workbook.js                — разбор Excel-файла базы субподрядчиков на категории
    storage.js                 — слой хранения (сейчас localStorage, см. ниже)
    srf.js                     — поля RFQ и сопоставление SRF → RFQ (детерминированно, без ИИ)
    api.js                     — вызовы к бэкенду (сейчас — только /api/srf/extract)
  components/
    Sidebar.jsx                — боковое меню
    CategoryDashboard.jsx      — главный экран: поиск, фильтры, сетка категорий
    CategoryDetail.jsx         — просмотр категории: список+карточка / таблица
    FieldRow.jsx                — поле карточки с кнопкой копирования (email/телефон)
    RfqScreen.jsx               — экран генерации RFQ из SRF
```

## Локальный запуск

**Одной командой (после первичной настройки):**

```bash
# один раз — установить зависимости в каждой части
cd frontend && npm install && cd ..
cd backend && python3 -m venv venv && source venv/bin/activate && pip install -r requirements.txt && cd ..

# в корне проекта — установить concurrently и дальше запускать одной командой
npm install
npm run dev
```

Поднимет фронтенд (`localhost:5173`) и бэкенд (`localhost:8000`) вместе, в одном
терминале, с цветными префиксами `[frontend]`/`[backend]` в логах.

**Важно:** если бэкенд стоит в venv, перед `npm run dev` в корне убедитесь, что venv
активирован в этом же терминале (`source backend/venv/bin/activate`) — иначе
команда `uvicorn` не найдётся. Проще всего один раз поставить зависимости бэкенда
глобально без venv (`pip install -r backend/requirements.txt`), тогда `uvicorn`
всегда будет на PATH и активировать ничего не нужно.

**По отдельности (если что-то пошло не так с общей командой):**

```bash
# терминал 1
cd frontend && npm run dev

# терминал 2
cd backend && uvicorn main:app --reload --port 8000
```

## Текущий статус и что предстоит на бэкенде

**Работает уже сейчас (без бэкенда, прямо в браузере):**
- Загрузка Excel-файла базы субподрядчиков, разбор на категории (`lib/workbook.js`, библиотека `xlsx`)
- Просмотр, поиск, фильтрация, редактирование записей
- Экспорт категории обратно в `.xlsx`

**Требует бэкенда (пока не реализован):**
- `POST /api/srf/extract` — чтение полей SRF (PDF). На реальном файле проверено: SRF экспортируется
  как настоящая таблица (с границами ячеек), поэтому Python-библиотека `pdfplumber` читает поля по
  подписям полностью детерминированно, без ИИ. Ожидаемый ответ:
  ```json
  {
    "requestorName": "", "department": "", "projectName": "", "projectNumber": "",
    "proposedSuppliers": "", "srfNo": "", "srfDate": "", "summaryDescription": "",
    "items": [{ "description": "", "startDate": "", "finishDate": "", "quantity": "", "uom": "" }]
  }
  ```
  Сопоставление этих полей с полями RFQ уже реализовано на фронтенде (`lib/srf.js`, функция
  `mapSrfToRfq`) — бэкенду достаточно вернуть сырые значения.
- Генерация финального `.docx` RFQ с точным сохранением оформления шаблона (`python-docx`,
  копирование стиля ячеек) — сейчас на экране RFQ показывается только предпросмотр полей.
- Аналогичный серверный шаг понадобится для сохранения оформления при работе с шаблонами Excel
  других категорий (не только чтение, но и построчная дозапись с копированием стиля).
- Хранение данных (`lib/storage.js`) сейчas на `localStorage` — при подключении бэкенда нужно
  заменить реализацию этих трёх функций на вызовы API; остальной код менять не придётся.
